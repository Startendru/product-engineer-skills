# Набор скиллов «дизайн-система» — план реализации

> **Для агентов-исполнителей:** ОБЯЗАТЕЛЬНЫЙ СУБ-СКИЛЛ — `superpowers:executing-plans`
> (или `superpowers:subagent-driven-development`). Шаги помечены чекбоксами (`- [ ]`).
> Каждый скилл создаётся по `superpowers:writing-skills`: RED (прогон без скилла) →
> GREEN (написать) → REFACTOR (закрыть лазейки). **Писать скилл до прогона RED запрещено.**

**Цель:** плагин `design-system` из пяти скиллов, который ведёт проект от «экраны есть,
системы нет» до живой дизайн-системы с заслоном в CI.

**Архитектура:** пять скиллов сцеплены предусловием на входе и именованной передачей на
выходе. Четыре нейтральны к стеку, `showcase` требует Next.js + Tailwind. Артефакты копятся
в `design-system/` целевого проекта: `inventory.md` → `tokens.json` → `registry.json` +
`registry.html` + `patterns/`.

**Стек:** Markdown (SKILL.md и справочники), Node.js ESM без зависимостей (скрипты
генерации html и заслона), Playwright или Chrome DevTools MCP (замеры в браузере).

**Спека:** Traycer-артефакт `2026-08-31-ds-skillset` эпика
`a2d1ace6-97dc-45b5-b5b8-26717f0a6504`. План спорит со спекой — читать оба.

## Global Constraints

Эти требования входят в каждую задачу неявно.

- Репозиторий: `Startendru/product-engineer-skills`, маркетплейс `startend`.
- Новый плагин: **`design-system`**, рядом с `startend` и `first-customer-finder`.
- Имена скиллов **без префикса `ds-`**: `inventory`, `tokens`, `registry`, `showcase`,
  `adopt`. Вызов — `design-system:<skill>`.
- Язык всех `SKILL.md` и справочников — **русский**.
- Аудитория — **нетехнический пользователь**: объяснять простыми словами, не требовать
  чтения кода.
- `inventory`, `tokens`, `registry`, `adopt` — **нейтральны к стеку**. Только `showcase`
  знает про Next.js и Tailwind.
- Каждый скилл начинается **предусловием**: нет артефакта предыдущего шага — остановиться
  и назвать, что вызвать. Заканчивается **именованной передачей**: назвать следующий шаг и
  что он получит.
- **Ни один артефакт не читают в исходнике.** У `.json` есть html-просмотр.
- Артефакты целевого проекта — в папке `design-system/` его корня.
- Frontmatter: `name` — только строчные буквы, цифры и дефисы. `description` — по образцу
  `plugins/startend/skills/design-leading-trim/SKILL.md`: суть, затем «Использовать при …»
  со списком формулировок пользователя, затем условия применимости. Русский, третье лицо,
  **без пересказа порядка работы скилла**.
- Порог контраста берётся **по худшей поверхности проекта**, не по типовой.
- Заслон **пропускает узлы, у которых предок несёт `background-image`**.
- Заслон **проверяется мутациями**: сломать каждое правило по очереди и удалить проверку
  целиком — всё должно ронять CI.
- Статус `ready` **запрещён при доле внедрения ниже 100%**.
- Каталог паттернов — **29 позиций** в трёх справочниках, ровно по спеке.
- **Лестница соблюдения.** Проектировать сверху вниз: (1) валидатор артефакта — скилл
  поставляет скрипт проверки схемы и обязан его прогнать; (2) предусловие — отказ стартовать
  без входного файла; (3) образец выхода — скелет для заполнения; (4) запреты и красные
  флаги — **только там, где машинной проверки быть не может**. Если требование проверяется
  скриптом, оно не живёт в прозе.
- **Не опираться на силу модели.** Скилл обязан работать на слабой модели. Соблюдение
  обеспечивает валидатор, а не догадливость агента.
- **Форма по скиллам:** `inventory`, `tokens`, `registry` — контракт артефакта плюс
  валидатор. `showcase` и `adopt` — контракт плюс дисциплинарная часть (мутационная
  проверка заслона и запрет `ready` при доле ниже 100% машинно не проверяются).
