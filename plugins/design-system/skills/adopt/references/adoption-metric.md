# Как считать долю внедрения

Доля внедрения отвечает на один вопрос: **сколько мест в продукте уже берут компонент из
системы, а сколько идут мимо.** Не «готов ли компонент» — на это отвечает статус.

## Единица счёта — место вызова, а не файл

«Кнопка используется в 38 файлах» и «кнопка вызывается 87 раз» — разные утверждения.
Мигрировать придётся вызовы, поэтому считаются вызовы. Число файлов полезно отдельно: оно
показывает, насколько работа размазана по проекту, но объём работы измеряет не оно.

| Что | Как считается |
| --- | --- |
| `migrated` | Вызовов компонента из системы |
| `total` | Всех вызовов этой роли в продукте: мигрированные плюс идущие мимо |
| Осталось | `total − migrated`. Именно это число и есть план работ |

Сырая вёрстка — тоже реализация роли и тоже попадает в знаменатель. Место, где кнопка
собрана вручную из `<button>` с классами, — это место, которое не берёт компонент из
системы, а значит, оно ровно то, что доля и обязана показывать.

## Доля — отдельное поле, а не часть статуса

Это два разных измерения, и слияние теряет одно из них.

| | О чём говорит | Кто на него влияет |
| --- | --- | --- |
| `status` | Зрелость самого компонента: есть ли варианты, состояния, доступность | Тот, кто пишет компонент |
| `adoption` | Состояние продукта: сколько экранов уже переехало | Тот, кто мигрирует экраны |

Компонент может быть отличным и внедрённым на 13%. Компонент может быть внедрён везде и
при этом оставаться черновиком без состояния загрузки. Одно поле такую пару не выражает.

**Поэтому 100% при статусе `draft` — законное сочетание**, и проверка его пропускает:
все места переехали, но компонент ещё дозревает. Обратное сочетание — `ready` при доле
ниже 100% — не законное никогда.

## Знаменатель — единственная подвижная часть

Числитель подделать трудно: вызовов компонента столько, сколько их в коде. А знаменатель
можно уменьшить, объявив часть мест «не считающимися», — и доля поднимется сама, без
единой миграции.

Поэтому **место выводится из знаменателя только с записанной причиной**:

```json
"exclusions": [
  {
    "where": "components/markdown-editor/toolbar.tsx",
    "count": 9,
    "reason": "разметку кнопок панели задаёт сторонняя библиотека редактора, мы её не контролируем"
  }
]
```

Проверка требует, чтобы причина была длиннее тридцати знаков. Порог не про красоту: он
отсекает «не считается», «исключение», «особый случай» — формулировки, которые нельзя ни
прочитать, ни оспорить. Причина, которую можно оспорить, — нормальная работа. Причина,
которую нельзя, — это ручка громкости на знаменателе.

## Пересчитывать в момент заявления, а не переносить

Числа из прошлого аудита, из комментария в коде или из старой записи реестра **не
являются подсчётом**. Живое дерево проекта меняется ежедневно: пока идёт миграция, вызовы
переезжают пачками, и число, верное неделю назад, сегодня неверно.

В базовой линии этого скилла агент взял 104 и 86 из комментария в шапке компонента — там
была записана история («форк 104 вызова, россыпь голых 86») — и выдал её за замер. На тот
момент форк был уже удалён.

**Комментарий в коде описывает намерение автора. Доля описывает состояние продукта.
Это разные вещи, и вторая берётся только пересчётом.**

## Поля записи

```json
"adoption": {
  "migrated": 139,
  "total": 226,
  "countedBy": {
    "migratedTags": ["Button"],
    "legacyTags": ["RegisterButton", "FilterChip"],
    "rawTags": ["button"]
  },
  "exclusions": []
}
```

| Поле | Смысл |
| --- | --- |
| `migrated` | Целое ≥ 0. Вызовов компонента из системы |
| `total` | Целое ≥ 0. Всех вызовов роли, за вычетом исключённых |
| `countedBy.migratedTags` | Имена, которыми вызывается компонент системы |
| `countedBy.legacyTags` | Имена параллельных реализаций той же роли: форки, старые компоненты |
| `countedBy.rawTags` | Нативные теги для ручной сборки: `button`, `input`, `select` |
| `exclusions[]` | Места, выведенные из знаменателя, — с местом, числом и причиной |

`countedBy` существует затем, чтобы **проверка пересчитала ваши числа сама**. Она берёт
теги, считает вхождения по исходникам проекта и сверяет с заявленным. Расхождение — это
отказ, а не предупреждение.

Без `countedBy` запись со статусом `ready` проверку не проходит. Стопроцентная доля,
которую никто не пересчитал, ничем не отличается от желаемой.

## Роли без нативного тега

У кнопки, поля и списка есть нативный эквивалент, и `rawTags` работает. У карточки,
алерта, вкладок его нет: считать их по `<div>` бессмысленно — в проекте сотни `div`, и ни
один из них не «сырая карточка».

Для таких ролей `rawTags` оставьте пустым, а ручную сборку внесите в `legacyTags` по
собственному признаку — имени скопированной переменной с классами (`cardCls`,
`ALERT_CLS`) либо имени локального компонента-двойника. Признак назовите в `note`, чтобы
следующий человек пересчитал тем же способом, а не своим.

## Область счёта

По умолчанию считается весь проект, кроме сборочных папок, тестов и того, что продуктом не
является: `node_modules`, `.next`, `dist`, `coverage`, а также `docs`, `artifacts`, `public`
и `storybook-static`.

Последние четыре попали в список по итогу прогона: в `docs/` целевого проекта лежали
выгруженные html-отчёты, и в них нашлось **264 тега `<button>`** — знаменатель раздувался с
224 до 488, доля падала с 85% до 39%. Ошибка была в безопасную сторону, но метрика, в
которой больше половины знаменателя не про продукт, бесполезна одинаково.

Если этого мало, сузьте область явно:

```json
"countedBy": {
  "migratedTags": ["Button"],
  "rawTags": ["button"],
  "roots": ["app", "components"]
}
```

Сужение честнее расширения: оно записано в реестре, и следующий человек посчитает так же.
Молча посчитать «только по нужным папкам» и вписать результат — нельзя, проверка пересчитает
по всему проекту и не сойдётся.

## Почему не посчитать руками через grep

Потому что счёт руками ошибается тихо. Реальный пример из работы над этим скиллом:

```
grep -rEo '<Button(\s|/|>)' --include='*.tsx' app components | wc -l   →  85
```

Правильный ответ — **192**. В расширенных регулярных выражениях BSD (то есть на macOS)
`\s` не значит «пробел»: выражение поймало `<Button/` и `<Button>`, но не `<Button ` с
атрибутами — то есть самую частую форму вызова. Ошибка вдвое, без единого сообщения.

Проверка считает сама и тем же способом каждый раз. Число, полученное собственной командой,
годится, чтобы себя перепроверить, но в реестр идёт то, что подтвердил пересчёт.

## Как доля выглядит человеку

Читать `registry.json` глазами не нужно. Проверка выпускает рядом `adoption.md`: таблица
записей, отсортированная по доле снизу вверх, с колонкой «осталось» и колонкой «что
мешает». Самая незакрытая запись оказывается первой строкой — это и есть подсказка, с чего
начинать следующую пачку.
