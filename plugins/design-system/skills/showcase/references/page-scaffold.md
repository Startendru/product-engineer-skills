# Каркас витрины

Витрина — обычный экран приложения по адресу `/design-system`. Она собрана **из тех же
компонентов, что и продукт**: не картинки, не описания, а живые кнопки, которые можно нажать
и провести по ним клавиатурой. Скриншот стареет молча, живой компонент — нет.

Стек: Next.js (App Router) и Tailwind. На другом стеке идея та же, разметка своя.

## Разделение данных и отрисовки

`registry.json` — данные: что за компонент, какого уровня, в каком состоянии зрелости,
сколько экранов переведено. В нём **нет** ссылок на код: реестр читают и заслон, и генератор
html, и человек, и он обязан оставаться нейтральным к стеку.

Связка «запись реестра → настоящий компонент» живёт отдельно, в одном файле витрины:

```tsx
// app/design-system/_demos.tsx — стеко-зависимый слой. Всё, что знает про React, здесь.
import { Button } from '@/components/ui/button'
import { Input } from '@/components/ui/input'

export const demos: Record<string, (variant: string, state: string) => React.ReactNode> = {
  button: (variant, state) => (
    <Button variant={variant} disabled={state === 'disabled'}>Действие</Button>
  ),
  input: (variant) => <Input placeholder="Текст" aria-invalid={variant === 'invalid'} />,
}
```

Запись реестра, для которой в этой карте нет строки, показывается заглушкой — и это
правильное поведение, а не пробел в вёрстке. См. ниже.

## Разделы витрины — по уровням реестра

Порядок разделов повторяет уровни: **атомы → молекулы → организмы → шаблоны страниц**.
Внутри раздела — по одной карточке на запись.

```
/design-system
├── Шапка: доля внедрения по продукту, дата сборки реестра
├── Атомы            кнопка, поле, бейдж, чекбокс…
├── Молекулы         поле с подписью и ошибкой, карточка…
├── Организмы        таблица, форма, диалог…
├── Шаблоны страниц  каркас экрана, пустое состояние…
└── Матрица контраста
```

## Карточка записи

Одна карточка — одна запись реестра. Обязательные части:

| Часть | Откуда | Зачем |
| --- | --- | --- |
| Название и уровень | `title`, `level` | по чему искать |
| Статус | `status` | `ready` / `draft` / `missing` — видно с одного взгляда |
| Доля внедрения | `adoption` | «12 из 61» честнее, чем «внедрено» |
| Живые варианты | `variants[]` × карта отрисовки | каждый вариант — настоящий компонент |
| Живые состояния | `states[]` | наведение, нажатие, отключено, **фокус** |
| Заметка о доступности | `a11y` | что именно обещано и должно работать |
| Где применяется | `usedOn[]` | куда идти смотреть в бою |

Состояние фокуса показывается **как состояние**, а не описанием: по витрине проходят
клавишей Tab, и если индикатор невидим, это видно сразу. Это единственный способ поймать
случай, когда индикатор объявлен и фактически неразличим.

## Записи `missing` показываются заглушкой с причиной

Соблазн — не выводить то, чего нет: витрина выглядит полной. Ровно поэтому так делать
нельзя. **Реестр — карта работ, а витрина — её отражение.** Спрятанная запись превращает
дыру в системе в невидимку, и её не берут в работу, потому что о ней никто не помнит.

```tsx
{entry.status === 'missing' ? (
  <div className="rounded border border-dashed border-rd-line p-6 text-rd-muted">
    <p className="font-semibold">Компонента нет</p>
    <p className="mt-1 text-sm">{entry.note}</p>
    {entry.blockedBy?.length ? <p className="mt-1 text-sm">Ждёт: {entry.blockedBy.join(', ')}</p> : null}
    <p className="mt-2 text-sm">Экранов собирают вручную: {entry.adoption.total}</p>
  </div>
) : (
  demos[entry.id]?.(variant, state) ?? <MissingDemo id={entry.id} />
)}
```

Заглушка сообщает три вещи: чего нет, почему, и сколько мест это уже стоит. Последнее число —
единственное, что переводит «когда-нибудь сделаем» в очередь по приоритету.

Отдельно: `demos[entry.id]` может отсутствовать и у записи со статусом `ready` — компонент
есть, а в карту отрисовки его не внесли. Это тоже заглушка, с другим текстом: «в реестре
есть, на витрину не выведен».

## Раздел матрицы контраста

Матрица берётся из `tokens.json` и **пересчитывается на живой странице**, а не переносится
числами из файла. Причина простая: между сборкой токенов и сегодняшним днём цвет мог
поменяться, а число в json — остаться.

```tsx
const ratio = contrast(hexOf(role), hexOf(surface))   // считается в браузере, при отрисовке
```

Строки с принятым `waiver` показываются с причиной, а не прячутся: осознанно принятый провал
остаётся видимым.

## Чего на витрине быть не должно

| Не надо | Почему |
| --- | --- |
| Скриншоты компонентов | устаревают молча, а выглядят как правда |
| Копия кода компонента в разметке витрины | появляется второй источник правды, и они разъезжаются |
| Только «хорошие» состояния | витрина нужна ровно для отключённого, ошибочного и пустого |
| Скрытые `missing` | дыра перестаёт быть видимой и выпадает из плана |

## Проверка витрины перед сдачей

1. Страница открывается, разделов столько же, сколько уровней в реестре.
2. Число карточек равно числу записей реестра. **Сверить счётом, а не на глаз.**
3. Каждая запись `missing` показана заглушкой с причиной.
4. Проход клавишей Tab: индикатор фокуса виден на каждом интерактивном элементе витрины.
5. Матрица контраста показывает числа, посчитанные страницей, и они сходятся с `tokens.json`.
