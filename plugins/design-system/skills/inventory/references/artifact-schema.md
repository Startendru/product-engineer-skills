# Схема `inventory.json`

Артефакт — данные. Читаемый `inventory.md` генерируется из него проверкой и руками не
правится: правьте json и перезапустите `node scripts/check-inventory.mjs <путь> <корень проекта>`.

Все счётчики — **целые числа ≥ 0**. Строки «много», «около 20» и пропущенные поля проверку
не проходят: инвентаризация без чисел не инвентаризация.

## Поля

### `project`
| Поле | Тип | Смысл |
| --- | --- | --- |
| `root` | строка | Корень проекта, от которого считаются пути |
| `componentsRoot` | строка | Папка компонентов. По умолчанию `components` |
| `filesScanned` | целое | Сколько файлов интерфейса просмотрено |

### `controls[]` — системы контролов
| Поле | Тип | Смысл |
| --- | --- | --- |
| `role` | строка | Роль: `button`, `input`, `select`, `checkbox`, `chip` |
| `totalUsages` | целое | Всего вызовов роли. **Пересчитывается проверкой** — должно сойтись с суммой |
| `implementations[].name` | строка | Имя реализации. Для сырой вёрстки — вида `raw <button>` |
| `implementations[].source` | строка либо `null` | Файл компонента. `null` у сырой вёрстки |
| `implementations[].usages` | целое | Число вызовов |
| `implementations[].files` | целое | В скольких файлах встречается |

**Обязательно:** у каждой роли должна быть реализация «сырая вёрстка». Если её нет —
впишите с `usages: 0`, чтобы было видно, что её искали.

**Считать по тегу можно только роли с нативным эквивалентом** — кнопка, поле, список,
многострочное поле, подпись, ссылка, форма, таблица, диалог. У карточки, алерта и вкладок
нативного тега нет: считать их по `<div>` бессмысленно, в проекте сотни `div`. Для таких
ролей назовите реализацию «ручная сборка» и посчитайте по своему признаку.

### `deadComponents[]` — компоненты без импортов
| Поле | Тип | Смысл |
| --- | --- | --- |
| `source` | строка | Путь к файлу |
| `imports` | целое | Обязан быть `0` — по определению мёртвого компонента |

Пусто — ставьте `[]`. Отсутствие поля проверку не проходит: иначе непонятно, искали или нет.

### `surfaces[]` — фоны, несущие текст
| Поле | Тип | Смысл |
| --- | --- | --- |
| `color` | строка | Hex вида `#rrggbb` |
| `token` | строка либо `null` | Имя токена. `null`, если цвет объявлен мимо палитры — это находка |
| `textNodes` | целое | Сколько текстовых узлов лежит на этом фоне |
| `screens` | целое | На скольких экранах встречается |
| `contrastFailures` | целое | Сколько пар не прошли норму |

### `typeScale` — шкала кеглей
| Поле | Тип | Смысл |
| --- | --- | --- |
| `declared[].px` | число | Размер |
| `declared[].occurrences` | целое | Вхождений |
| `distinctSizes` | целое | **Пересчитывается проверкой** — должно совпасть с длиной `declared` |
| `scaleTokenUsages` | целое | Обращений к шкале фреймворка вместо произвольного размера |

Отношение `distinctSizes` к `scaleTokenUsages` — главный признак: много разных размеров при
малом числе обращений к шкале означает, что шкалы нет, а размеры подбираются каждый раз.

### `tokens[]` — палитра
| Поле | Тип | Смысл |
| --- | --- | --- |
| `name` | строка | Имя переменной |
| `value` | строка | Значение |
| `usages` | целое | Употреблений. **Ноль — находка**: токен объявлен и мёртв |

### `pageStructure[]` — структура экранов
| Поле | Тип | Смысл |
| --- | --- | --- |
| `url` | строка | Экран |
| `mainLandmarks` | целое | Число главных лендмарков. Больше одного — дефект |
| `h1` | целое | Число заголовков первого уровня. Не единица — дефект |
| `headings` | целое | Всего заголовков. Ноль — экран без иерархии |

Эти три числа собираются здесь, а чинятся позже, на уровне шаблонов страниц. Инвентаризация
их только фиксирует.

### `outOfScope[]` — что не относится к системе

Массив путей. Файл — точным путём, папка — с косой чертой на конце: `components/markdown-editor/`
закрывает всё внутри.

Нужен, потому что проверка требует учесть **каждый** файл компонента: он должен попасть в
реализации, в мёртвые или сюда. Иначе параллельная реализация просто не попадает в
инвентарь, а это главная находка шага. Признать папку не относящейся к системе — нормально;
не заметить её — нет.

### Честность про замер
| Поле | Тип | Смысл |
| --- | --- | --- |
| `measuredInBrowser` | булево | Делались ли замеры в браузере |
| `notMeasured[]` | массив строк | Что осталось непроверенным |

При `measuredInBrowser: false` массив `notMeasured` **обязан быть непустым**. Пропустить
замер можно, сделать вид, что его не было нужно, — нельзя.

## Что проверка ловит

| Проверка | Какую ошибку закрывает |
| --- | --- |
| Все счётчики — целые числа | Отчёт-пересказ без единого числа |
| `totalUsages` пересчитывается | Заявленная сумма, не сходящаяся с составом |
| `distinctSizes` пересчитывается | Заявленное число, не сходящееся со списком |
| У роли есть сырая вёрстка | Посчитаны только компоненты, ручная сборка пропущена |
| `deadComponents[].imports === 0` | Мёртвым назван компонент, у которого есть импорты |
| `notMeasured` непуст при `false` | Замер молча пропущен |
| **Вызовы пересчитываются по коду** | Заявленные числа, не имеющие отношения к проекту |
| **Каждый файл компонента учтён** | Пропущенная параллельная реализация — главная находка шага |
| **Компоненты без импортёров ищутся сами** | `deadComponents: []` при живых мёртвых компонентах |
| Тесты исключены из подсчёта | Вызов из теста засчитан за употребление в продукте |
