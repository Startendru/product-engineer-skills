# Оптическая обрезка строчного бокса

## Что происходит

Вертикальные отступы CSS отмеряются не от букв, а от границ **строчного бокса**. Их задают метрики гарнитуры, зашитые в файл шрифта: `ascent` резервирует место под диакритику и высокие элементы, `descent` — под выносные хвосты (`р`, `у`, `д`, `ц`, `щ`). Браузер честно отмеряет `padding` от этих границ, а глаз видит границы **глифов**. Разница между ними и есть воздух, из-за которого текст в кнопке, баннере или плашке стоит не по центру.

Три следствия, каждое из которых стоит починки:

- **Отступ зависит от шрифта.** Величина воздуха — свойство гарнитуры. Две гарнитуры в одном проекте дают разный оптический результат при одинаковом `mt-4`. Смена шрифта двигает весь вертикальный ритм, и связать одно с другим потом почти невозможно.
- **Код не совпадает с макетом.** Figma обрезает этот воздух внутри себя (настройка *vertical trim*) — всегда обрезала. Отсюда вечное «вёрстка на два пикселя не такая».
- **Шкала отступов врёт.** `8 / 16 / 24` означают «8 плюс сколько-то». Токену, который не равен своему значению, перестают доверять, и отступы снова начинают подбирать на глаз.

Хуже всего заметно в CAPS: у заглавных нет нижних выносов, а `descent` под них зарезервирован.

## Диагностика

### Метрика решает всё

Наивные способы замера дают **неверную картину**. Проверено на практике:

| Что мерить | Почему не работает |
| --- | --- |
| Расстояние до фактических «чернил» строки (`actualBoundingBox` от самого текста) | Зависит от того, какие буквы попались. Слово «прозрачные» без высоких букв покажет перекос 5 px там, где его нет |
| Расстояние между границами блоков (`getBoundingClientRect`) | После обрезки `margin` не меняется — разница будет ровно нулевой, хотя слипание видно глазами |

**Правильная метрика — оптический зазор:** от базовой линии верхнего блока до верха заглавных нижнего. Только она совпадает с тем, что видит глаз.

### Замер метрик гарнитуры

Запустить в браузере на живой странице. Даёт перекос в долях `em` — числа, из которых потом считается всё остальное:

```js
() => {
  const cv = document.createElement('canvas').getContext('2d')
  const out = {}
  // перечислить гарнитуры проекта
  for (const f of ['Inter', 'Onest', 'system-ui']) {
    cv.font = `400 100px "${f}", serif`
    const H = cv.measureText('H')
    const asc = H.fontBoundingBoxAscent, desc = H.fontBoundingBoxDescent
    const cap = H.actualBoundingBoxAscent
    out[f] = {
      'сверху над заглавной': +((asc - cap) / 100).toFixed(4),
      'снизу под baseline': +(desc / 100).toFixed(4),
      'перекос': +(((asc - cap) - desc) / 100).toFixed(4),
    }
  }
  return out
}
```

Перекос до `±0.005 em` — пренебрежим. От `0.02 em` — заметен на крупных кеглях: умножить на кегль, получить пиксели.

### Поиск текста, не отцентрированного в боксе

Это второй, независимый случай — и чаще именно с него приходит жалоба: «текст в кнопке съехал вверх». Проверять надо отдельно, потому что предыдущий скрипт ищет расстояния **между** блоками, а здесь дефект **внутри** одного.

Ищет боксы, где текст центрируется флексом, а `padding` сверху и снизу одинаковый — значит всё расхождение пришло из метрик:

```js
() => {
  const cv = document.createElement('canvas').getContext('2d')
  const out = []
  document.querySelectorAll('body *').forEach((box) => {
    const cs = getComputedStyle(box)
    if (!/flex/.test(cs.display) || cs.alignItems !== 'center') return
    // В колонке align-items центрирует по ГОРИЗОНТАЛИ — это не наш случай
    if (/column/.test(cs.flexDirection)) return
    const pt = parseFloat(cs.paddingTop), pb = parseFloat(cs.paddingBottom)
    if (Math.abs(pt - pb) > 0.5) return          // несимметричный padding — намеренный
    const rk = box.getBoundingClientRect()
    if (!rk.height) return

    // носитель текста: единственный текстовый ребёнок либо сам бокс
    const deti = [...box.children].filter((c) =>
      (c.textContent || '').trim() && !c.querySelector('svg') && !c.classList.contains('sr-only'))
    const el = deti.length === 1 && !deti[0].children.length ? deti[0] : box
    const t = (el.textContent || '').trim()
    if (!t || t.length > 24) return

    const es = getComputedStyle(el)
    const fs = parseFloat(es.fontSize)
    cv.font = `${es.fontStyle} ${es.fontWeight} ${fs}px ${es.fontFamily}`
    const H = cv.measureText('Н')                 // заглавная нужного алфавита
    const lh = es.lineHeight === 'normal' ? fs * 1.2 : parseFloat(es.lineHeight)
    const r = el.getBoundingClientRect()
    const cap = H.actualBoundingBoxAscent
    const obr = es.textBoxTrim && es.textBoxTrim !== 'none'
    const half = (lh - (H.fontBoundingBoxAscent + H.fontBoundingBoxDescent)) / 2
    const capTop = obr ? r.top : r.top + half + H.fontBoundingBoxAscent - cap
    const baseline = obr ? r.bottom : r.bottom - half - H.fontBoundingBoxDescent

    const perekos = (capTop - rk.top) - (rk.bottom - baseline)
    // Порог зависит от ФОРМЫ: в круге и квадрате глаз ловит асимметрию острее.
    // Круг — это не «радиус больше половины высоты»: под такое описание попадает
    // и кнопка-пилюля, у которой оптического центра нет. Нужны ещё квадратные
    // пропорции.
    const kvadrat = Math.abs(rk.width - rk.height) < 2
    const kruglyy = kvadrat && parseFloat(cs.borderRadius) >= rk.height / 2 - 1
    const porog = (kruglyy || kvadrat) ? 0.4 : 0.6
    if (Math.abs(perekos) < porog) return

    out.push({ txt: t.slice(0, 18), teg: el.tagName.toLowerCase(),
      forma: kruglyy ? 'круг' : kvadrat ? 'квадрат' : 'прямоугольник',
      sem: es.fontFamily.split(',')[0].replace(/['"]/g, ''),
      kegl: +fs.toFixed(1), obrezan: !!obr, perekos: +perekos.toFixed(2) })
  })
  return out
}
```

**Форма контейнера меняет порог.** Полпикселя в кнопке теряются — глазу не от чего отсчитывать. Те же полпикселя в круглом аватаре видны сразу: окружность задаёт чёткий оптический центр. Поэтому круглые и квадратные боксы — аватары, счётчики, иконочные кнопки с буквой — проверяются первыми, даже когда перекос формально ниже общего порога.

### Поиск слипшихся пар

Ищет соседние блоки, где оптический зазор мал. Порог: под заголовком **0.35 кегля заголовка**, между прочими блоками **0.25 кегля меньшего**.

```js
() => {
  const cv = document.createElement('canvas').getContext('2d')
  const linii = (el) => {
    const cs = getComputedStyle(el), r = el.getBoundingClientRect()
    const fs = parseFloat(cs.fontSize)
    cv.font = `${cs.fontStyle} ${cs.fontWeight} ${fs}px ${cs.fontFamily}`
    const H = cv.measureText('H')
    const lh = cs.lineHeight === 'normal' ? fs * 1.2 : parseFloat(cs.lineHeight)
    const pt = parseFloat(cs.paddingTop), pb = parseFloat(cs.paddingBottom)
    const bt = parseFloat(cs.borderTopWidth), bb = parseFloat(cs.borderBottomWidth)
    const cTop = r.top + bt + pt, cBot = r.bottom - bb - pb
    const cap = H.actualBoundingBoxAscent
    // если высота контента ≈ capHeight, обрезка уже применена
    const obrezano = Math.abs((cBot - cTop) - cap) < 1.5
    const half = (lh - (H.fontBoundingBoxAscent + H.fontBoundingBoxDescent)) / 2
    return obrezano
      ? { capTop: cTop, baseline: cBot }
      : { capTop: cTop + half + H.fontBoundingBoxAscent - cap,
          baseline: cBot - lh + half + H.fontBoundingBoxAscent }
  }
  const ZAG = new Set(['H1','H2','H3','H4','H5','H6'])
  const out = []
  document.querySelectorAll('main *, body *').forEach((rod) => {
    const deti = [...rod.children].filter((e) =>
      (e.textContent || '').trim() && e.getBoundingClientRect().height > 0)
    for (let i = 0; i < deti.length - 1; i++) {
      const a = deti[i], b = deti[i + 1]
      const ra = a.getBoundingClientRect(), rb = b.getBoundingClientRect()
      if (rb.top < ra.bottom - 1 || Math.abs(ra.left - rb.left) > 4) continue
      const kegl = parseFloat(getComputedStyle(a).fontSize)
      const opt = linii(b).capTop - linii(a).baseline
      const porog = ZAG.has(a.tagName) ? 0.35 : 0.25
      if (opt / kegl < porog) out.push({
        teg: a.tagName.toLowerCase() + '→' + b.tagName.toLowerCase(),
        kegl: +kegl.toFixed(1), zazor: +opt.toFixed(1),
        doli: +(opt / kegl).toFixed(2), porog,
        txt: (a.textContent || '').trim().slice(0, 26),
      })
    }
  })
  return out
}
```

**Дедуплицировать результат** по `тег + кегль + зазор`: одна правка в общем компоненте обычно закрывает десятки строк отчёта. Иначе список выглядит как «40 мест», а источников там восемь.

## Починка

### Механизм

```css
text-box: trim-both cap alphabetic;
```

Сверху режет по высоте заглавной, снизу по базовой линии. `cap alphabetic` — ходовой выбор для латиницы и кириллицы; для CJK существуют `ideographic` и `ideographic-ink`.

Поддержка: Chrome 133+ (февраль 2025), Safari 18.2+ (декабрь 2024), Firefox 154+ (август 2026) — Baseline newly available.

**Фолбэк в духе Capsize не делать.** Он был единственным решением до появления свойства, но сегодня это плохая сделка: зашитые в CSS отрицательные поля из метрик надо пересчитывать при каждой смене гарнитуры, и они молча врут, когда шрифт не загрузился и подставился фолбэчный. Деградация без фолбэка безопасна — в старом браузере текст остаётся таким, каким был.

### Свойство не наследуется

Это главная ловушка. Носителей текста надо перечислять поимённо:

```css
@layer base {
  :where(
    h1, h2, h3, h4, h5, h6,
    p, li, dt, dd,
    blockquote, figcaption, caption,
    label, legend,
    button, summary,
    th, td
  ) {
    text-box: trim-both cap alphabetic;
  }
}
```

`:where()` даёт нулевую специфичность — переопределяется без счёта весов.

`span`, `div` и `a` в список **не входят**: они бывают и контейнерами, и носителями, обрезать их поголовно значит трогать раскладку. Для них — точечные утилиты:

```css
@utility text-box-trim { text-box: trim-both cap alphabetic; }
@utility text-box-none { text-box: none; }
```

### Обрезка не работает во flex-контейнерах с анонимным текстом

`<button class="inline-flex">Текст</button>` обрезку **не получит**: текст лежит в анонимном flex-элементе, а обрезать можно только блочный контейнер. Обычно это не беда — там текст центрируется через `align-items`, и перекос равен перекосу шрифта. Если гарнитура кнопки даёт заметный перекос, обернуть текст в `<span class="text-box-trim">`; учесть, что высота кнопки при этом уменьшится.

**Отдельно проверить места, где внутри флекса стоит вторая гарнитура.** Это самый частый живой пропуск: правило перечисляет теги, `span` в него не входит по замыслу, а именно в `span` обычно и оказывается текст, набранный дисплейной гарнитурой — инициалы аватара, число счётчика, значение показателя. Разница между гарнитурами бывает пятнадцатикратной: на боевом проекте Inter давал 0.0025 em, Onest — 0.0374 em, и инициалы вставали выше центра круга на 0.7 px при том, что кнопки рядом выглядели нормально.

**Не трогать текст, который выравнивается относительно соседа, а не бокса.** Число оценки рядом со звёздами, подпись рядом с иконкой, значение рядом с единицей измерения — там глаз сравнивает текст с соседним элементом, и обрезка сдвинет его относительно этого соседа. Порог тот же, а решение другое: выравнивать по базовой линии (`align-items: baseline`) либо не трогать вовсе.

### Ритм придётся перенастроить

**Это обязательная часть работы, а не побочный эффект.** Обрезка убирает воздух, а вертикальные отступы подбирались с его учётом. На реальном проекте страница «схлопнулась» на 559 px, заголовки сели на текст.

Правило после обрезки: **под заголовком не меньше 0.35 его кегля**, между прочими блоками — не меньше 0.25 кегля меньшего из них. Округлять до шага шкалы.

| Заголовок | Кегль | 0.35 кегля | Шаг шкалы 4 px |
| --- | --- | --- | --- |
| display-xl | 56 px | 19.6 | `mt-5` · 20 |
| h3 | 28.8 px | 10.1 | `mt-3` · 12 |
| h4 | 20.8 px | 7.3 | `mt-2` · 8 |

И правило дисциплины на будущее: **отступ задаётся только шагом шкалы**. Если расстояние выглядит неверным, меняется шаг, а не подбирается число.

## Заслон

Правило ломается молча — текст просто встаёт выше центра, ничего не падает. Поэтому нужна проверка в CI. Она статическая: сверяет теги-носители, найденные в разметке, с перечисленными в правиле, и падает, если правило исчезло или потеряло `trim-both`.

Логика проверки:

1. Пройти исходники, собрать теги из списка носителей, встречающиеся как `<tag` (регулярка `<${teg}(?=[\s>/])`, иначе `<p` поймает `<path>` и `<pre>`).
2. Вынуть из CSS список тегов внутри `:where(...)` перед `text-box:`. **Вырезать комментарии до разбора** — иначе фраза с двоеточием в комментарии прочитается как объявление.
3. Упасть, если найденный в разметке тег отсутствует в правиле, или если правила нет вовсе.

**Проверить заслон мутациями:** убрать один тег из правила и удалить правило целиком — обе должны ронять проверку. Заслон, который никогда не видели красным, не заслон.

## Когда не применять

- **На большом живом сайте без визуального regression-теста.** Включение — одна строка, а вот ревизия всех вертикальных отступов разом — это регрессия во всех местах одновременно. Переход дёшев только на старте проекта; предупредить об этом до начала работы.
- **Когда перекос гарнитуры меньше 0.005 em** и других гарнитур в проекте нет: выигрыша не будет, а ритм перенастраивать придётся.

## Порядок работы

1. Замерить метрики гарнитур — понять, есть ли проблема и в какой из них.
2. Оценить с заказчиком стоимость: переход требует перенастройки ритма. На старте дёшево, на живом сайте дорого.
3. Внести правило и утилиты.
4. Замерить, что схлопнулось — **по оптическому зазору**, не по границам блоков.
5. Отдельно прогнать поиск текста, не отцентрированного в боксе: это независимый случай, и правило по тегам его не закрывает. Круглые и квадратные контейнеры — первыми.
6. Перенастроить ритм по правилу 0.35 кегля, дедуплицируя источники.
7. Поставить заслон и проверить его мутациями.
8. Показать результат глазами: скриншот до и после на одном и том же экране.
